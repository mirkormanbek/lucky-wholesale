# Кабинет склада Lucky

Режим «Партия»: до 8 фото, каждое создаёт отдельный товар с собственным артикулом. Категория, цена и необязательные характеристики вводятся один раз; названия получают номер варианта. Цвет можно оставить пустым и уточнить в каждой карточке. Партия менеджера отправляется владельцу на проверку; ИИ-обработка и публикация выполняются отдельно после проверки. Повтор того же запроса не создаёт дубликаты, данные всей партии сохраняются атомарно. Режим «Один товар · несколько ракурсов» сохраняет все фото в одной карточке.

Каждый цвет — отдельный товар. «Добавить другой цвет» копирует данные сохранённой модели в новый товар без переноса фото. Только явно связанные таким способом модели показывают переключатель вариантов в публичной карточке; переключение меняет артикул и товар в заявке. Обычная партия разных рисунков не объединяется автоматически. В публичной карточке доступны все ракурсы через миниатюры.

Работает на Plesk с PHP 7.4+. GitHub Pages показывает основной статический каталог, серверный кабинет работает только на Plesk.

Путь `/warehouse/` должен быть защищён средствами Plesk. Проверка роли на сервере использует `REMOTE_USER`: `meiram` — владелец, остальные авторизованные пользователи — менеджеры. Для менеджера создайте отдельный логин в защищённом каталоге. Логин владельца задан один раз в `public/warehouse/storage.php`. Пароли и ключи в репозитории отсутствуют.

Форма: фото → вид спорта → тип товара → цена. Название формируется автоматически из `fields.json` или имени категории; его можно уточнить в свёрнутом блоке. Материал, размеры и цвета необязательны. Варианты берутся из категории. Частые цены рассчитываются по доступным пользователю товарам. Родительские категории нельзя выбрать вместо конкретного типа.

Менеджер сохраняет черновик или отправляет товар на проверку. Владелец видит общую очередь, редактирует данные, запускает платную ИИ-обработку, принимает либо отклоняет результат, возвращает с комментарием, публикует или снимает товар. Сервер проверяет права; скрытие кнопок не служит защитой. Версия записи предотвращает перезапись изменений с другого устройства. При редактировании опубликованный товар возвращается на проверку.

После явного принятия обработанного фото владельцем оригинал удаляется с сервера. Отклонение результата сохраняет оригинал. При ошибке обработки оригинал сохраняется. Публикация доступна только после принятия всех оставленных в карточке фото. Повторная обработка принятого фото требует загрузки нового ракурса. Уже загруженные, но удалённые из незавершённой карточки фото автоматически не очищаются; это отдельный этап обслуживания хранилища.

Закрытая папка — соседняя с document root: `lucky-wholesale-private/`. Там хранятся `openai-key.php`, JSON базы, блокировка и оригиналы/результаты. Папка должна быть доступна PHP для записи и находиться вне document root. Созданный пользователем ключ не изменяется. cURL и Fileinfo должны быть доступны. API редактирования: gpt-image-1.5, medium, 1024×1024; явный запуск, максимум 10 попыток в сутки по UTC, включая ошибки, без автоматических повторов. Этот предел ограничивает запросы, а не гарантирует сумму расходов.

`warehouse-catalog.php` и `warehouse-photo.php` находятся вне защищённого каталога и отдают только опубликованные товары/принятые фото. Оригиналы публично не отдаются. Основной app.js добавляет складские товары к каталогу WB; недоступность складского API не блокирует каталог WB. Общая база находится вне public и не затрагивается sync-wb.yml, build-catalog или FTP-деплоем. Защиту Plesk не переносить в GitHub; FTP mirror не использует --delete и не удаляет существующую .htaccess.

Старые локальные черновики можно перенести кнопкой «Перенести старые черновики» на том устройстве/в том браузере, где они сохранены. Перенос не удаляет локальную копию и пропускает уже существующие идентификаторы. Локальные черновики с родительской категорией требуют уточнения типа перед переносом. Складские фотографии не включены в резервное копирование GitHub: настройте резервное копирование закрытой папки в Plesk отдельно.

Проверено локально с PHP 7.4.33 и Chromium: два отдельных браузерных контекста менеджера/владельца, общая запись без обязательных характеристик, автоматическое название, роли и доступ к чужим фото/товарам, запрет публикации неподтверждённого результата, сохранение отдельного результата ИИ (тестовый ответ), физическое удаление оригинала после принятия, публикация и снятие, публичные изображения, конфликт версии, мобильная и широкая вёрстка. Живой платный вызов OpenAI не выполнялся. Синтаксис всех PHP-файлов и JavaScript проверен.

Перед работой менеджера проверить на Plesk: вход отдельным логином менеджера, сохранение/передача тестового товара, видимость владельцу, тест обработки, принятие, публикация и снятие. Защищённая папка не должна открываться без входа. Не присылать ключи и пароли в чат.
