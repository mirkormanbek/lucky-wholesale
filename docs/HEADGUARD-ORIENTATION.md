# One shared headguard composition

All five headguard categories, in category and model modes, use the same source-driven prompt in HEADGUARD-PROMPT.txt. No SKU, brand, color or named helmet type selects a different wearing template.

The composition separates two responsibilities:
- Source product photos control orientation, topology, material, markings and attachment points.
- One category-wide portrait style controls the close crop, lighting and strong athletic expression. A shout is allowed only when compatible with the actual protection and natural fit.

The supplied RDX portraits establish mood and framing. They are not sent as product evidence, and their cage, silhouette, branding, clothing or wearer's identity must not transfer to another product.

The prompt handles the general conditions: sideways/upside-down/loose source pose; separate or connected padding; existing or absent cage/face bar/shield/chin protection; original fastenings; natural anatomical contact and guard clearance. It does not classify products into hard-coded geometry types or invent unseen components.

Original images plus one image-edit request remain the runtime path. No added inspection stages, per-product prompts, compulsory manager reference uploads or automatic publication. Other product categories keep their existing behavior.

Validation boundary: category/mode tests demonstrate that every headguard category receives the identical prompt and candidates require manual acceptance. These are not visual fidelity tests. Earlier built-in previews are not equivalent to production API validation. Production gpt-image-1.5 testing across representative source constructions remains pending; no claim of universal visual accuracy or safety certification is made.
