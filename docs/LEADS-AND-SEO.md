# Заявки, Telegram и серверный каталог

## Что изменено

На Plesk работает PHP 7.4+ и обычный JavaScript. Новый серверный вход `public/index.php` использует существующий HTML-шаблон, выдаёт первую страницу каталога прямо в HTML и передаёт опубликованные данные интерактивному каталогу. Данные WB проходят через существующий `wb_public_products()`, складские товары — через проверку `published` и одобренных фото. Кабинет, цены и фотостудия не переписываются.

`/product/<id>` — постоянная страница товара с описанием, размерами, ценой, метаданными, Open Graph и JSON-LD. `/sitemap.xml` включает только опубликованные товары. Цена берётся из каталога/кабинета и пересчитывается по существующим курсам. Если цена не задана, показано «Цена по запросу»: выдуманных цен нет.

`public/site-config.php` — один файл условий опта и общих текстов/контактов. Там меняются минимум 5 шт., предоплата, склады и доставка. `public/media/og-wholesale.png` — PNG 1200×630 для главной; для товара используется его первая фотография.

## Переменные окружения на хостинге

Задать именно в окружении процесса PHP/FPM:

| Имя | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Секретный токен вашего бота от BotFather |
| `TELEGRAM_CHAT_ID` | Числовой ID личного чата менеджера или группы; у группы часто начинается с `-100` |
| `YANDEX_METRIKA_ID` | Только числовой ID счётчика; пустое значение отключает Метрику |

`.env.example` содержит только имена без значений. PHP читает `getenv()`; загрузчика `.env` нет. Не помещайте значения в HTML, JavaScript, GitHub, `.htaccess` или файлы в публичной папке. На Plesk наличие полей для переменных зависит от настроек тарифа: если таких полей нет, попросите поддержку задать эти три переменные для PHP-FPM домена `opt.luckysport.kz` и перезагрузить его пул. У PHP-FPM окружение может очищаться; поддержке нужно явно разрешить переменные в конфигурации пула. Пример имён директив для администратора: `env[TELEGRAM_BOT_TOKEN]`, `env[TELEGRAM_CHAT_ID]`, `env[YANDEX_METRIKA_ID]`. Значения передавайте поддержке только приватно.

Нужны расширение PHP cURL, рабочий системный набор доверенных CA-сертификатов и исходящий HTTPS к `api.telegram.org:443`. Закрытая папка `lucky-wholesale-private` находится рядом с корнем сайта, а не внутри него; существующая папка кабинета используется также для файла ограничений заявок. Доступ к ней нужен пользователю PHP. Нужны Apache 2.4 с `mod_rewrite` и разрешённым `.htaccess`. Если сайт работает только на nginx, поддержка должна настроить аналогичные маршруты: `/` → `index.php`, `/product/<id>` → `product.php?slug=<id>`, `/sitemap.xml` → `sitemap.php`. Нельзя раздавать PHP как текст.

Без токена/chat_id форма честно покажет ошибку и контакты, а не ложное подтверждение отправки. При пустом ID Метрики её внешний скрипт не загружается.

## Создать Telegram-бота — по шагам

1. В Telegram найдите **@BotFather** с отметкой официального аккаунта. Напишите `/newbot`.
2. Задайте имя бота, затем свободное имя пользователя, заканчивающееся на `bot`.
3. BotFather выдаст токен. Это пароль бота: не присылайте его в публичный чат и не записывайте в репозиторий.
4. Откройте созданного бота по ссылке от BotFather. Менеджер должен нажать **Start / Запустить** или отправить `/start`: бот не может первым начать обычную личную переписку.
5. Для заявки в группу добавьте бота в нужную группу и отправьте там команду с упоминанием бота, например `/start@имя_вашего_бота`.
6. Задайте `TELEGRAM_BOT_TOKEN` в локальном окружении. Запустите `php scripts/telegram-chat-id.php`. Помощник выводит только числовые ID и типы обнаруженных чатов, без токена и текста переписки. Выберите чат менеджера/группу и скопируйте его ID в `TELEGRAM_CHAT_ID`.
7. Если чатов нет — отправьте боту `/start` и повторите помощник. Если у существующего бота установлен webhook, помощник не удаляет его: для проверки проще создать отдельного тестового бота.
8. Перенесите токен и выбранный ID в окружение PHP на хостинге. Перезапустите PHP-FPM через панель/поддержку.

Официальные инструкции: [создание бота](https://core.telegram.org/bots/tutorial), [getUpdates и sendMessage](https://core.telegram.org/bots/api).

## Реальный тест локально

Нужен **действующий тестовый бот**, а не вымышленная строка токена. Node.js 20+ и PHP 7.4+ с cURL должны быть доступны локально.

В PowerShell из корня проекта:

```powershell
# Если php не находится автоматически, укажите путь к php.exe:
$env:PHP_BIN = 'C:\путь\к\php.exe'
# Скрипт запросит токен скрытым вводом, при необходимости покажет chat_id,
# запустит локальный PHP и отправит ровно одну тестовую заявку:
.\scripts\Test-Telegram-Lead.ps1
```

Если портативному PHP нужны дополнительные параметры, `PHP_TEST_ARGS` принимает JSON-массив аргументов PHP, например настройки `extension_dir`, `extension=php_curl.dll`, `curl.cainfo`. Секреты в аргументы командной строки не передаются. Помощник использует переменные только в процессе и восстанавливает прежние значения после теста.

Либо при уже заданных `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`:

```powershell
node scripts/live-lead-test.mjs
```

Сообщение помечено **«ТЕСТ — не заявка клиента»**. После подтверждения Telegram помощник сохраняет `work/telegram-live-proof.json`: время, `message_id`, ID запроса и тестовые поля. Токена там нет. Это подтверждение принятия сообщения Telegram, а не прочтения менеджером. Автоматических повторов нет. При неизвестном результате используйте прямую связь, не запускайте тест много раз подряд.

## Сборка и проверки

```powershell
node scripts/build-storefront.mjs
php tests/leads-domain.test.php
node tests/leads-integration.cjs
```

Для интеграционного теста можно указать `PHP_BIN` и `PHP_TEST_ARGS`. Это **локальный mock Telegram**, не сообщение в настоящем Telegram. Он проверяет настоящий PHP/cURL → локальный HTTP-приёмник, валидацию, Origin/заголовок, honeypot, ограничение 5/10 минут, защиту от дублей и неопределённой доставки, SSR, валюты, sitemap, XSS и скрытие черновиков.

Браузерная проверка включается через `RUN_BROWSER_TESTS=1`, `PLAYWRIGHT_MODULE` (путь к установленному Playwright) и `CHROME_PATH` (путь к Chrome). В ней проверяются форма, каталог и товар на 360 px, заполнение товара, успех/ошибка с контактами, одна цель после успеха и HTML при отключённом JavaScript. Telegram и Яндекс в этом тесте имитируются локально.

`build-storefront.mjs` проверяет PHP/JS, общий шаблон и OG-картинку, синхронизирует корневые preview-файлы с `public/`. Сборка импорта WB остаётся отдельной: `node scripts/build-catalog.mjs`; ей нужен исходный `data/products.json`, который создаёт `sync-wb.mjs` с рабочим WB API token. Этого сырого снимка нет в чистом репозитории; отсутствие снимка не заменяется пустым каталогом и не удаляет опубликованные товары.

Локальный запуск для разработки:

```powershell
php -S 127.0.0.1:4235 -t public scripts/dev-router.php
```

Действующие Telegram-переменные следует задавать **до** запуска PHP. `.env.example` сам по себе их не включает.

## Цель Яндекс Метрики

1. Создайте счётчик в Яндекс Метрике для `https://opt.luckysport.kz` и скопируйте числовой ID.
2. Задайте его как `YANDEX_METRIKA_ID` в окружении PHP на хостинге.
3. В Метрике откройте **Настройка → Цели → Добавить цель**.
4. Название: **Заявка отправлена**. Тип: **JavaScript-событие / целевое событие**. Идентификатор: **`lead_sent`**.
5. Сохраните цель и отправьте тестовую заявку. Цель вызывается только после серверного `ok: true`, то есть после подтверждения Telegram. Ошибки, нажатие кнопки и клиентская валидация целью не считаются. Телефон, имя и комментарий в цель не передаются. Вебвизор отключён; DNT/GPC соблюдаются.

[Документация reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal).

## Доставка и защита

Телефон валидируется в браузере и PHP. Личный номер с начальной `8` для 11 цифр приводится к `+7`. Для KZ/RU проверяются 11 цифр и код +7; для других стран — международный формат 8–15 цифр. Подлинность номера без SMS не подтверждается.

Обработчик принимает только JSON с собственного origin и специальным заголовком. Honeypot не отправляет сообщение. Лимит — 5 новых валидных попыток с `REMOTE_ADDR` за скользящие 10 минут; `X-Forwarded-For` от клиента не доверяется. В хранилище — только HMAC-ключи IP/запроса, времена и статусы, не содержание заявки. При новом обращении записи старше 10 минут очищаются. Сервер не повторяет неопределённую отправку. Ответ об успехе возвращается только после `ok: true` и `message_id` от Telegram. Передача ограничена таймаутом 8 секунд; сроки внешнего сервиса не гарантируются.

Данные Telegram выводятся обычным текстом, без HTML/Markdown-разметки. В сообщении есть все поля, время Asia/Almaty, страница и UTM. Для старых PHP с tzdata до 2024 года учтён переход Алматы на UTC+5 ([IANA 2024a](https://www.iana.org/time-zones/releases/2024a)).
