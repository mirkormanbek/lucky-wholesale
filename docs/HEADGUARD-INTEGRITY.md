# Проверка соответствия шлема: v4, ручное принятие обязательно

Проблема: ограничений текста недостаточно. Генератор может добавить решётку, а прежний путь принимал любой корректный PNG как вариант.

Новая цепочка только для портретов шлемов:
1. Responses API, gpt-4.1-mini: независимый инвентарь конструкции по оригинальным изображениям. При неопределённости генерация не запускается.
2. Images API: один кадр с оригиналами товара и инвентарём. Необязательный референс остаётся отдельной ролью.
3. Responses API, gpt-4.1-mini: сравнение оригиналов и кандидата. Отказ при добавленной/удалённой конструкции, изменённых маркировках/цвете, сомнительной посадке или неопределённости.
4. При отказе или недоступности проверки кандидат удаляется, не попадает в карточку. Проверенные варианты сохраняются отдельно и требуют принятия владельцем. Сервер не разрешает принять вариант v4 без отметки пройденной проверки.

Счётчик запросов: не более одного анализа, одной генерации и одного сравнения за подтверждение, без автоматических повторов. При раннем отказе оплаченный анализ/генерация не возвращаются автоматически. UI отдельно сообщает о двух дополнительных платных проверках. Старые клиенты без integrityConfirmed не запускают этот путь.

Нужен доступ серверного ключа к Responses и gpt-4.1-mini. Ключ не выводится и не попадает в Git. Responses store=false. Изображения кодируются в JSON потоком через закрытый временный файл; base64 не собирается полностью в памяти. Исходники суммарно до 16 МБ, время каждого review-вызова до 25 секунд, без повторов. Временные файлы удаляются. Оригиналы и текущая галерея при отказе сохраняются.

Ограничения: это вероятностная модельная проверка, не геометрический симулятор и не подтверждение защитных свойств. Возможны ложные пропуски и ложные отказы. Текст инвентаря сам по себе не является доказательством. Проведён один согласованный реальный контрольный тест на жёлтом Reyes: 1 анализ, 1 генерация и 1 сравнение. Сервис вернул кандидат без добавленной решётки и прошедший проверку. Первичная ручная претензия к перекрытию рта пересмотрена после изучения конструкции face-bar: само перекрытие рта бампером не доказывает ошибку. При этом точная посадка, скрытая конструкция и перенос маркировки не подтверждены. Анализатор может ошибаться (в этом тесте он назвал bumper отсутствующим); нельзя считать его инвентарь истиной. Покрытие других конструкций реальными тестами пока не подтверждено. Поэтому сохраняется обязательное ручное сравнение и принятие владельцем.

Локальные проверки:
- PHP 7.4 lint / JS syntax.
- tests/studio-review.test.php: строгий разбор, отказ при противоречивом passed+issues, неопределённости, отказе провайдера, неверных полях, потоковый base64 и серверный запрет принятия.
- PHP/cURL -> mock API: нет подтверждения, неясный исходник, added_structure, недоступная проверка, pass, запрет дублирования и сохранность оригиналов.
- Локальные имитационные проверки не затрагивали API и производственные данные. Отдельно владелец выполнил согласованный реальный тест; сайт и каталог им не изменялись.

Официальные схемы: https://developers.openai.com/api/docs/guides/images-vision и https://developers.openai.com/api/docs/guides/structured-outputs
