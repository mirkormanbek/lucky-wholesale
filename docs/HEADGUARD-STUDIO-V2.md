# Портреты шлемов: новый сценарий

Для категорий шлемов режимы «Кадр категории» и «На модели» используют отдельный prompt, а не общий prompt одежды.

1. Выбрать оригинальные фотографии товара.
2. В отдельном поле загрузить фото аналогичного шлема на человеке, задающее посадку.
3. Референс отправляется последним изображением с отдельной ролью. Его бренд, цвет и конструкция не должны копироваться.
4. Сохраняется один отдельный результат; галерея не меняется автоматически. В метаданных отмечаются headguard-v2 и fitReferenceUsed.
5. Проверить посадку, форму товара и маркировку перед принятием.

Сервер откажет до платного вызова при отсутствии референса, при выбранном сохранённом ИИ-результате вместо оригинала или при виде не спереди. Если оригинал удалён после прежнего принятия фото, необходимо загрузить его заново. Автоматического восстановления удалённых файлов нет.

Референс принимается как временная загрузка JPEG/PNG/WebP до 12 МБ/40 мегапикселей, не попадает в каталог и не сохраняется в галерею. Клиентский флаг проверки не считается доказательством загрузки: сервер удаляет его и валидирует файл самостоятельно. Авторизация владельца и CSRF-ограничения сохранены. Оценка стоимости включает дополнительное изображение. Режим предметного белого фона остаётся прежним.

Синтаксис и тесты PHP: tests/studio-headguard-v2.test.php, tests/studio-headguard.test.php, tests/studio-headguard-sport.test.php. Локально проверен реальный multipart PHP/cURL -> mock API: роль последнего изображения, запрет поддельного флага, три входных изображения, метаданные, отсутствие изменений галереи. Не использовались производственные данные и платные запросы.

Это не гарантирует геометрическую точность результата. Контрольная генерация и сравнение с оригиналом и фото посадки обязательны перед утверждением качества. Изменение модели API в эту задачу не входит.
